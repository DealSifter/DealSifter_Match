# Runtime orchestration root-cause trace — before implementation

Production source baseline: `a02951fe06db81b27a75ec9995ec5e93165ab592`. Local HEAD `25bc9bd` only adds production receipts; `src` / `supabase` match the source baseline.

| Defect | Existing path and exact cause | Scoped correction |
| --- | --- | --- |
| LAND input/state loss | `MaxxisAssistant.submitMessage` → `resolveLocalLandDevelopment` → `parseLandDevelopmentAssumptions` → `resolveDealScenario`. Parser recognizes houses/SFR, not SFH or zoning. Zoning-only input is discarded without an existing development scenario. Local replies only update the 20-message transcript; persistence is exposed only for COMPLETE scenarios. `maxxis-analysis-inputs.dealAssumptions` rejects typed development fields. `scenarioEngine.compactScenarioInputs` omits zoning. DecisionContext only recognizes canonical zoning and an opaque developmentAssumptions string. | Extend these existing contracts; persist explicit typed assumptions even with PARTIAL outputs. Keep user zoning separate from verified canonical facts and LAND separate from proposed SFR. |
| Gap/topic hijack | `submitMessage` selects the latest gap in all history without property/strategy/version scope, reparses answers after intent classification, and `classifyMaxxisConversationIntent` parses gap answers before explicit analytical topics. `buildMaxxisSmartActions` prioritizes decision gaps for every structured response; explanation can become generic deal insight with a financing CTA. | Explicit topic classification first, scoped optional gap continuation, deterministic market explanation, suppress unrelated primary actions. |
| LAND valuation refusal | Land-price colloquial questions have no dedicated deterministic intent. `maxxis-chat.resolveMandatoryToolCall` does not capture them, so Gemini can produce a generic refusal. Existing `selectDevelopmentComparables` already supports strict recorded SOLD LAND reference math but is not invoked for raw-land value questions. | Use existing sold-evidence engine and freshness policy; deterministic LAND acquisition reference independent of development completeness. No gate loosening or new math. |
| Comparables/Matches confusion | `MaxxisCapabilities.ACTION_DEFINITIONS` exposes generic `matches`; `MaxxisAssistant.handleAction` forwards unknown/string actions into app navigation. There is no valuation-domain action contract, so a model-issued matches action can navigate to the social network. | Explicit comp-evidence action types with captured property/version, evidence-only execution; preserve explicit DealSifter Matches action. |
| Report chat fallback | Report CTA opens selector and its handoff invokes generic `submitMessage(prompt)`. Local routes run before report ownership; returned USER_INPUT_REQUIRED gate creates `analysis_gap_resolution` and returns before report projection. | Typed report operation owns routing immediately. Analytical incompleteness remains report content, never a creation gate. Retain entitlement and technical failure behavior. |
| Internal prompt leak | Handoff carries `request.prompt`; generic submit defaults visible user content to `cleanMessage`. Smart follow-ups and some action handlers call submit with generated prompts but no visible label. | Separate execution message from mandatory localized action label, hide internal payload in transcript, and validate scoped action before execution. |

No migration, report visual/page redesign, arithmetic changes, pricing changes, provider-guard changes, avatar changes or new WOW feature is in scope.
