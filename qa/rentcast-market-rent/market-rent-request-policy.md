# Acquisition policy

Explicit current-property Market Rent question or the existing action chip is
acquisition intent. Unrelated financial/readiness queries are cache-only. The
frontend never contacts RentCast; Gemini never acquires financial evidence.
Service checks entitlement before cache access, resolves current authorized
subject inputs, checks fingerprint + freshness, then coalesces identical misses.
The provider owns the existing plan/bucket and application Usage Guard. No new
usage counter. Disabled provider cannot acquire. Cache visibility retains product
entitlement. Public-address privacy gate precedes subject construction.

Existing report family acquisition permissions are not expanded. Their authorized
rent family delegates to this same controlled path; merely rendering/exporting a
report consumes already-authorized evidence and never calls RentCast. No bootstrap,
Portfolio, card, Edit/Page2, route-navigation or readiness-only acquisitions.

Errors distinguish not queried, no result, temporary failure, entitlement, budget,
disabled, review required, unsupported, address missing and unit context required.
Only normalized failure attempts are cached (no raw error or user-specific denial).
Property row writes: zero. Private assumptions never enter provider request/cache.
