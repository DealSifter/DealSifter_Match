## Comp gates e semânticas exatas

Dois sistemas coexistem: `compEngine` de AVM e `soldCompEngine` com `weightedCompPolicy`. AVM gate só SFR(single family)/condo/townhouse; price/sqft>0; proximidade boa<=1mi, distante>3mi; recente<=90dias/stale>180; size variance preferred<=.2/material>.4; lot>.5/year>20/bedbath>1 penalizam. Ausência de delta é tratada como0 nesses checks antigos, ocultando penalidade, não comprovando compatibilidade.

Sold weighted balanced pesos: subdivision10, roadBarrier5, distance12, type12, story5, living15, year7, lot6, beds5, baths5, pool3, garage3, other2, recency8, freeway2. `structural=100*earnedWeight/availableWeight`; `completeness=100*availableWeight/applicableWeight`. Unknown não pesa como incompatibilidade, mas derruba completude. Classe excellent>=90/valid>=80/support>=70; primary>=80 + complete>=65 + hardGates pass + distance<=1mi OU sameSubdivision. Secondary path tem regras próprias em soldCompEngine; não confundir com recent-sales<=5mi. Inspecionar overrides antes de mudar threshold global.

ARV exige condição USER_PROVIDED revisada; UNREVIEWED fica MARKET_REFERENCE, superior/inferior SUPPORTING, incompatible EXCLUDED, partial não core por default. Pode haver comp estrutural excelente sem um único comp de ARV. Isso explica resultados inconclusivos sem provar bug de promoção. `arvEngine.ts` dispersion ratio moderate1.25/high1.5/extreme2.25, CV .15/.25/.5; dois comps intervalo observado $/sqft; 3–5 baixa dispersão intervalo interquartil, alta observado. Divergência central>=10% gera warning. Não atribuir qualidade final ao valor AVM.

Hard gates weighted concretos (`weightedCompPolicy.ts::hardGates`): recordedSalePrice finito>0, data de venda parseável, provider ID OU APN OU endereço utilizável, tipo presente/compatível, livingArea>0 com diferença de área conhecida, sem saleTransactionAmbiguous nem hardInvalidReasons. Distance factors balanced<=.5mi1/<=1mi.9/<=2mi.6/<=3mi.35/>3mi0; livingArea delta<=200sqft1/<=400.85/<=600.7/<=800.45, maior mas variance<=.4 recebe.2. Outros cenários têm fatores próprios. Recent-sales exige data não futura, sale evidence VERIFIED_RECORD, price/áreas positivos, tipo igual e distance<=5; age>policy passa a historicalReference. Não confundir esses gates com revisão de condição ARV.

LAND não usa retrospectivamente venda de casa pronta para preço do terreno. `DEVELOPMENT_COMP_POLICIES`: LAND_ACQUISITION max size variance.75; FINISHED_HOME_EXIT .4, preferNewConstruction=true. recent-sales calcula referência sem ajuste de condição; projetar saída com proposed-home baseline, nunca comparar casa futura com vacant parcel. Dados reais de zoning/permit/acesso não foram validados.
