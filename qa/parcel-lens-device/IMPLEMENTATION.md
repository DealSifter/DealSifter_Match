# Device-aware Parcel Lens / camera integrity

All individual PIN selections and Spotlight-card selections now use the same selection camera and Z15. Magnifier activation uses Z17 on phones, Z16 on desktop/tablets; a repeated magnifier click restores the exact target zoom without repeating cached parcel queries. Phone landscape detection uses the coarse-pointer/small-height media query; ordinary tablet portrait remains Z16.

The requested 0.20 mi is treated as total diameter: radius 0.10 mi / 160.9344 m. Display, SVG circle and bounded neighbor queries use the same constants. This is geographic context, not a valuation or survey measurement.

Root causes removed: parcel activation re-fitted arbitrary polygon bounds with maxZoom20; page content changed native popup dimensions and triggered automatic panning; changing lens activation re-mounted the basemap; fit effects replayed their last command when sidebar padding changed; zoomend and moveend emitted duplicate React snapshots; coincident-pin display offsets changed during zoom; serialized geometry keys and nonmemoized geometry features increased unnecessary work.

The camera computes a device-safe, screen-space popup/PIN slot excluding sidebar, header controls, mobile footer and avatar area. Initial and public-parcel pages share an identical outer frame, including the optional owner drag footer. Small phones reserve room for the full lens above navigation. Long public data remains complete with internal scrolling. Tabs appear only after magnifier activation; the close control beside tabs was removed. Native popup close and the top diameter-pill close remain independent. Closing a popup does not remove the geographic lens.

The top pill is centered on phones and right-aligned beside the native +/- control on other devices. Source-limit/unavailable warnings remain accessible in an explicit disclosure without growing the camera layout. The selected native popup disables autopan; page changes and network responses cannot trigger another fit. Repeated actions cancel previous camera motion and register no delayed moveend/popup reopen callbacks. Parcel geometry objects and keys remain stable, and the basemap survives activation/closure without remounting.

Runtime QA uses the real local Leaflet/React UI with explicitly synthetic GIS geometry and mocked app authentication; existing basemap tiles are live. It does not impersonate a production user or claim live parcel-source/user-account acceptance. Five device/language/theme scenarios verify Z15 → Z16/17, exact width/height, <=1px projection rounding drift, no motion after tab changes, no overlay with avatar/menu/footer, repeat activation after manual zoom, and two cached queries. An isolated desktop check verifies Spotlight selection, independent close controls and preserved basemap DOM identity. A final small-phone check verifies full circle/footer clearance.

The original complete unit run passed 1,820/1,821 assertions; an unchanged land-report PDF assertion exceeded its explicit 30-second deadline under concurrent build load. The isolated retry and final camera suite are aggregated by distinct file; original reports remain retained, not presented as one clean full run. No PDF assertion/template was edited. The final compiled frontend is separately verified after the small-phone height correction.

Scope: frontend-only; no migrations, backend function publication, source/license changes, secrets, feature-flag/cohort expansion, paid providers, canonical fact changes, report changes or Maxxis parcel consumption. Existing internal-only production exposure is retained. Unrelated user audit artifacts are not staged.
