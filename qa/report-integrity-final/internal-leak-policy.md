# Internal artifact leak policy

No user-visible report content may contain raw domain/provider/model objects, serialized JSON, raw translation envelopes, internal field identifiers, reason codes, enum tokens or JavaScript coercion artifacts. This includes appendix and continuation content, not just the cover or valuation page.

## Structural prevention

- Typed ReportRow/ReportClaim/ReportTable data is generated by the strict projector; renderer inputs are safe localized primitives.
- Supported field paths and label registries are exhaustive for displayed concepts. An unknown concept is omitted/diagnosed, never humanized by underscore replacement or camelCase splitting.
- Translation has a strict acquisition/parser contract and cache-read validation. Only parsed narrative text reaches the model; arbitrary wrappers and nested payloads fail closed.
- Old structured/freeform report narratives do not automatically become evidence. Executive synthesis must match supported evidence refs and existing packet claims; otherwise deterministic fallback is used.
- Section continuation retains the section's title/schema. No preservedInformation/remainingContent dump page can bypass the same boundary.

## Final defensive scans

`validateRenderedReportText` rejects coercion artifacts (`[object Object]`, undefined, NaN, Infinity), serialized JSON, known backend field names and enums, and generic preserved-information dump titles. `scripts/report-integrity-qa.mjs` independently scans actual extracted PDF text for a broader set including field/column identifiers, internal status tokens, contradictory source labels and locale-specific English system-copy leakage. These guards supplement, not replace, typed projection.

A match is a release failure. Do not silently mask or strip individual leaked tokens from generated commercial PDFs. Fix the origin/projection and regenerate the artifact. Source notes and descriptions remain separate from system-generated intelligence; their presence does not authorize raw wrappers or backend payloads.

Required release evidence includes 30 actual PDFs, all extracted text and page rasters, source/binary hashes, zero/empty-section/leak audits, manual visual review bound to those binaries, and unchanged provider/performance controls. A previous QA PASS file or screenshot existence alone is not valid proof.
