# Release validation runner contract

`scripts/report-integrity-validation.mjs` never deploys or calls providers. Default / `--consolidate` only evaluates existing receipts. `--source` records source-before-build.json. `--binding` validates that pre-build digest, every current src/shared source against the actual build stage (default .cache/smart-property-release; --stage or REPORT_INTEGRITY_BUILD_STAGE override), dist/index.html and the checked Deno dependency hashes. It annotates build.json with the verified sourceDigest only after all actual binding checks pass. `--static` runs full frontend lint, contract TypeScript and strict report TypeScript. `--isolation` compares the exact 25 calculation/ARV/sold/area modules and MapView/parcel source with repository baseline 04950e1, rejects tracked or untracked migrations, and copies the pre-captured production frontend baseline receipt when present.

`--tests=targeted` executes the explicit report/origin/financial regression list. A comma-separated list selects exact local test paths. The full suite runs only for the explicit `--tests=full` argument. Before execution, tracked historical `qa/` files outside prefix `qa/report-integrity` are snapshotted byte-for-byte, including the user's existing dirty state. A finally block restores any changed/missing bytes and original absence. Snapshot files are retained under the task-owned .cache directory for recovery. Restoration failures fail the gate. Raw current-run Vitest JSON, log, compact counts, source hashes and preservation receipt are retained separately for targeted/full runs; a missing/startup-failed raw output cannot reuse an old PASS.

Source digest covers sorted normalized sources under src, supabase/functions, scripts and relevant root configuration. Static/tests capture before and after and fail if source changes during execution. Build/browser checks must likewise bind the actual checked assets to that digest, not stamp the current digest onto an old run.

Final consolidation requires all of the following, failing closed for missing/stale receipts:

- `targeted/tests.json`, `full/tests.json`, `static-checks.json`, `financial-engine-isolation.json`: pass and current matching sourceDigest.
- `golden-report-validation.json`: 30 rendered PDFs, six fixtures, with sourceHashes matching current files. Thirty per-report validation files must each pass and have an existing PDF with matching pdfSha256, extracted text and every page PNG. Required matrix: six L3 fixtures × PT/EN/ES (18 PDFs), plus LOW_EVIDENCE_SELL and RENTAL_MARKET_RICH each in L1 and L2 × PT/EN/ES (six L1 and six L2 PDFs). All renderer/image transports, RentCast/GIS and reopen provider calls must remain zero.
- `manual-visual-review.json`: pass and executiveWowPass, plus reviewedReports covering all six L3 fixtures. Each reviewed entry must include fixture, basename, pdfSha256 and pass; the hash must match a current passing actual L3 PDF. A statement without current binary binding is insufficient.
- `build.json`: pass and current sourceDigest from the actual build workflow.
- `source-binding.json`: passing current sourceDigest and verified staged app/Edge source identity.
- `deno-baseline-comparison.json`: pass, newErrors equal zero and sourceHashes matching current checked files (raw or newline-normalized).
- `browser-validation.json`: pass and current sourceDigest, realBackendWrites zero, reviewCases at least six, mapTransitions at least ten, photoHandoffs at least two, errors zero. The browser workflow must retain its underlying actual run receipts; synthetic auth/backend is not a real authenticated production smoke.

The final `quality-gates.json` records each requirement and exact missing receipt. It does not infer authenticated production PASS: without a legitimate session the authenticated production smoke remains BLOCKED. No partial one-fixture PDF run, stale image set, mock production data or lower-layer PASS can satisfy the final artifact gate.
